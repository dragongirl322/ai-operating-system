## 3. More complete summary: computer-use agent UX

The paper **"Mapping the Design Space of User Experience for Computer Use Agents"** is useful because it treats AI agents as systems that act inside existing interfaces, not just chatbots that answer questions. The researchers used a two-phase method: first, they reviewed existing computer-use agent systems and interviewed eight UX/AI practitioners to build a taxonomy; second, they ran a Wizard-of-Oz study with 20 participants across normal, error-prone, ambiguous, and risky web-task scenarios. Source: [arXiv / IUI 2026](https://arxiv.org/abs/2602.07283).

The taxonomy has four main design areas:

1. **User query.** How the user expresses intent, whether the query comes once or through conversation, whether input is text/voice/image, what user profile or contextual data is used, how ambiguity is resolved, and what safety policies govern allowed requests.

2. **Explainability of agent activities.** Whether users can see where the agent is acting in the UI, whether action history is retained, how actions/tool calls/reasoning/uncertainty are described, whether next steps are previewed, how plans and replanning are shown, and how runtime status is communicated.

3. **User control.** Stop, pause, take over, demonstrate a correction, revert to earlier steps, review or edit plans, approve high-impact actions, discover errors, understand errors, and recover from errors.

4. **Mental model and expectations.** What tasks the agent can perform, what controls are supported, what parts of the UI or device the agent can access, what external resources it can use, what personal data it can see, and what risks or mitigation mechanisms exist.

The strongest findings:

- Users want different autonomy depending on goal and risk. For a specific, low-risk task, they may want the agent to run end to end. For exploratory tasks, ambiguous choices, purchases, account changes, or social communication, they want clarification and collaboration.
- Visibility matters, but users do not want to babysit agents. The better pattern is progressive disclosure: lightweight status by default, deeper reasoning/action detail when the user asks or when risk increases.
- Plans are most valuable for long, unfamiliar, cross-app, or risky tasks. The plan should especially flag steps involving payment, account creation, personal data, irreversible changes, or communication with another person.
- A stop button is not enough. If the user has stepped away, the system needs error detection, notifications, checkpointing, and clear ways to resume, undo, or redirect.
- Trust depends on scope. Users need to know what applications, pages, data, credentials, files, microphones, contacts, and external tools the agent can access, and they need runtime control when the agent asks to expand that scope.
- Error recovery needs to be designed as a primary workflow: show where the error happened, explain it in plain language, preserve progress, allow branch-level undo, and let the user take over temporarily before handing control back.

For your work, the useful phrase is **delegation UX**. The design problem is not "make the assistant easier to prompt." It is: how does a human safely delegate action to a system that can see, click, infer, decide, and execute in interfaces originally designed for humans?

## 4. More complete summary: science-agent benchmarks

There are two different but complementary signals in the science-agent papers.

### SciConBench: evidence synthesis is still weak

**"Can AI Agents Synthesize Scientific Conclusions?"** introduces SciConBench, a benchmark of 9.11K questions and expert-written conclusions from systematic reviews, primarily relevant to health and scientific evidence synthesis. The authors evaluate whether AI systems can retrieve evidence, reason across sources, and produce conclusions that are both correct and comprehensive. Source: [arXiv, submitted June 9, 2026](https://arxiv.org/abs/2606.11337).

The important methodological move is **clean-room evaluation**. The authors argue that web-enabled agents can look better than they are if they retrieve the ground-truth systematic review or derivative summaries. SciConHarness blocks those ground-truth artifacts and evaluates whether the system can actually synthesize rather than shortcut.

Key findings:

- Under clean-room conditions, the best agent reached only **0.337 factual F1**.
- Without clean-room controls, performance was higher, which suggests leakage can inflate apparent capability.
- Consumer-facing systems were also unreliable even when ground-truth material was available. Google AI Mode, Google AI Overview, and OpenEvidence produced incomplete and sometimes contradictory conclusions.
- Common failure modes included wrong direction of effect, mischaracterizing evidence quality, and vague conclusions that missed specific caveats.
- Longer answers improved coverage somewhat but reduced precision, so verbosity did not solve reliability.

The design implication is that scientific and health-facing AI should not simply produce polished summaries. It needs claim-level provenance, uncertainty, contradiction detection, evidence-quality language, bounded recommendations, and expert review before decisions or actions depend on the output.

### SciAgentArena: agents are useful, but only in bounded research workflows

**"Benchmarking AI Agents for Addressing Scientific Challenges Across Scales"** introduces SciAgentArena, an interactive benchmark of roughly 200 scientific tasks with stepwise verification across drug discovery, single-cell omics, spatial omics, EHR modeling, genetics, and cross-domain biomedical tasks. Source: [arXiv, submitted June 10, 2026](https://arxiv.org/abs/2606.12736). Project site: [SciAgentArena](https://sciagentarena.github.io).

The core finding is not that agents are useless. It is more precise: current agents are strongest when the task is well specified, local, verifiable, and close to established data-analysis workflows. Reliability drops when tasks require novelty, open-ended exploration, multi-objective optimization, scientific skepticism, or validation of whether the user's premise is sound.

Recurring failure modes:

- Agents generate executable-looking code that uses nonexistent APIs, wrong functions, wrong object types, or stale package assumptions.
- Agents lose state across multi-step workflows: variable names, file headers, schemas, and intermediate outputs drift.
- Agents fall back to familiar methods instead of adapting to the scientific objective.
- Agents over-execute instead of challenging invalid, impossible, contradictory, or underspecified user requests.
- In biomedical and clinical tasks, agents struggle with trade-off reasoning, broad medication coverage, causal evidence, ancestry-aware integration, and robust validation.

The design implication is that "AI scientist" is the wrong default metaphor. A better design frame is **co-scientist with checkpoints**: use agents for bounded analysis, parsing, preprocessing, code generation, and standard workflow execution; require human review for causal claims, clinical safety, novelty, high-impact interpretation, and validation-sensitive decisions. The product surface should include stepwise verification, visible tool calls, data/schema checks, refusal or clarification for flawed premises, reproducible artifacts, and explicit handoff to domain experts.

## Design Leadership Takeaway

Items 2, 3, and 4 are the same story in different domains. Commerce agents, computer-use agents, and science agents all force the same design question: **what authority has the human delegated, how does the system prove it is still inside that authority, and how does the human recover control when it is not?**
